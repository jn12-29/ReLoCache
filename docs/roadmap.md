# TODO 与未来计划

更新日期：2026-09-15。

本文记录已讨论确定的工作方向、实施顺序和完成标准；未勾选项均为待完成工作，接口字段与具体实现尚未定稿。当前实现契约见 [接入说明](integration.md)。

## 当前基础

- 已有内容注册、显式/自动编译、Reader 引用、flush 和配置持久化 KV 层后的落盘能力。
- 已有 Base/LoRA Writer、Writer Pre/Post soft tokens 和独立的 Reader embeddings；KV Packet / Joint 当前支持未压缩路径。
- PIC 公开生成接口使用 Chat/Responses 的结构化内容引用；普通 completions 支持完整 token IDs，但尚无精确 token 内容块的公开 PIC 输入。
- `sempic_open` 当前只接入 teacher generation 与 `full_recompute`。已有 GPU 执行验证见 [README](../README.md)，不代表方法接入或正式质量、性能评测已经完成。

## 职责与实施约束

| 层 | 负责内容 |
| --- | --- |
| SemPIC | 方法与训练、checkpoint 导出、Writer 编译策略、prompt 与内容边界、数据集、评分和实验组织。 |
| ReLoCache | 内容表示、缓存身份、编译与复用语义、服务协议及轻量客户端。 |
| vLLM | 原生请求执行、KV 管理、调度、缓存查找与 offload；通过窄接口接入所需执行能力。 |

后续工作在已有能力上逐层扩展，优先复用原生接口和统计。协议实现后同步更新接入说明，删除被替代的旧路径。SemPIC 侧任务在本文中作为集成依赖跟踪；遵守当前仓库约定，旧 `sempic_open` 及其环境保持只读。

## 阶段一：精确输入与未压缩方法接入

目标：让调用方保留已准备好的 token 序列与内容边界，完成未压缩方法的服务生成流程。

### ReLoCache TODO

- [ ] 增加有序 token 内容块输入，组合普通 token IDs、可复用内容引用与 Reader embeddings，原样执行调用方提供的 tokens。
- [ ] 由服务端根据块顺序计算位置和 spans，按 Writer 包装后的完整逻辑长度推进 Reader 位置；客户端无需重复提交另一套位置描述。
- [ ] 将 token 输入与 Chat/Responses 渲染结果归一到共同的内部表示，保留普通消息服务的输入方式。
- [ ] 提供不依赖 vLLM 安装的轻量客户端类型，覆盖新增输入及内容编译结果。
- [ ] 统一内容相关错误的对外表达，包括未知内容、空来源和不满足持久化条件。

### SemPIC 集成依赖

- [ ] 导出标准 PEFT Writer、Writer/Reader soft tokens 与部署配置，服务端不读取研究 checkpoint 的内部布局。
- [ ] 将 canonical prompt 和内容边界映射到 token 内容块，连接生成结果、轨迹保存和评分流程。
- [ ] 接入 `no_recompute`、`sempic`、`kvpacket`、`sempic_kvpacket` 的未压缩评测，保留 `full_recompute` baseline。

完成标准：上述方法通过 API server 完成代表性质量评测，记录模型、方法产物与输入语义；精确 token 输入、包装位置和生成结果满足各自契约。跨引擎逐 token 输出相等不作为默认要求。

## 阶段二：缓存生命周期与复用可观测性

目标：支持离线编译、持续在线服务，以及能解释缓存收益的实验。

### 生命周期 TODO

- [ ] 支持按已注册内容 ID 显式编译，避免再次传输来源。
- [ ] 明确同一 ID 更新来源时，已提交请求与后续引用各自绑定的内容语义。
- [ ] 将本次编译和持久化的完成等待限定到其产生的工作，保留全局 `flush` 用于整体排空。
- [ ] 明确关闭自动编译后的 cache miss 行为，并对外返回可识别的失败原因；原生加载中的 KV 不作为编译缺失处理。
- [ ] 分别表达来源注册、编译完成、当前 KV 驻留与持久化结果，避免用长期有效的 `ready` 标志代替动态缓存状态。

### 指标与客户端 TODO

- [ ] 暴露 PIC 引用量与实际复用 KV tokens/pages，区分逻辑引用量和实际执行量。
- [ ] 记录自动编译数量、缓存加载来源与加载量，以及 Reader 等待编译或加载的时间。
- [ ] 记录 Reader 实际执行的 prefill token 数，复用原生 TTFT、排队、生成与 tracing 能力。
- [ ] 定义指标的范围和单位；编译、加载与调度可能重叠，不将其简单相加解释为总延时。
- [ ] 提供部署摘要查询，包含模型与 Writer 身份、soft-token 长度、自动编译及存储配置，供客户端选择请求和记录实验配置。
- [ ] 按调用需求补齐客户端流式消费，沿用服务端原生 streaming 与请求取消生命周期。

完成标准：在持续有其他请求的情况下，本次编译仍能独立报告完成；请求统计能够区分缓存复用、加载与自动编译。SemPIC 分别记录 SSD 冷缓存、热缓存或稳态实验的初始状态、reset 范围及指标口径。

## 阶段三：按方法需求扩展执行能力

本阶段由具体实验需求确定先做压缩还是选择性重算；每次完成一项可评测的执行能力。

### KV selection / reduction

- [ ] 支持编译后选择部分 KV 或产生缩减表示，由 SemPIC 定义选择或缩减策略。
- [ ] 分别表达源内容长度、存储 KV 行数、Reader 逻辑位置及必要的位置映射。
- [ ] 将表示变化纳入缓存身份与复用语义，接入原生 KV 存储和执行路径。

完成标准：以具体压缩方法完成输出与位置语义验证，并报告质量、实际 KV 存储量和执行开销；不能用压缩后的 KV 行数直接替代原始逻辑长度。

### 选择性重算

- [ ] 为具体方法提供复用内容内部分 token 重算的执行能力。
- [ ] 对 EPIC 等静态选择与 CacheBlend 等依赖中间结果的策略，按实际执行阶段扩展接口。
- [ ] 由 SemPIC 定义选择算法和参数，ReLoCache 表达复用与重算语义，vLLM 执行并管理 KV。

完成标准：选定方法通过服务接口完成质量与开销评测，能够说明实际重算范围及复用量。
